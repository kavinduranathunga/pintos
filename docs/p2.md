#### ALGORITHMS

>A2: Briefly describe how you implemented argument parsing.  How do you arrange for the elements of argv[] to be in the right order?
In process_execute(), we use strtok_r() to get only the program name (like "grep") to create the thread. In setup_stack(), we use strtok_r() again to split the full command line (like "grep foo bar") into separate words and push each word onto the stack. While pushing strings, we save their memory addresses in a local array called argv[].   

To put argv[] in the correct order on the stack:
    1. We align the stack pointer (*esp) to a 4-byte boundary.
    2. We push a NULL pointer first.   
    3. We loop backward through our argv[] array (from the last word to the first word) and push each pointer onto the stack. This puts argv[0] at the lowest address as required by 80x86 rules.   
    4. Finally, we push the address of argv[0], argc, and a fake return address (0).

>How do you avoid overflowing the stack page?
The command line string fits inside a single 4 KB page (4096 bytes). We also limit the maximum number of words using a fixed argv[128] array so the stack frame never goes outside the user stack page


#### RATIONALE

>A3: Why does Pintos implement strtok_r() but not strtok()?
strtok() uses a global hidden variable to keep track of its position in a string. In an OS with many threads running at the same time, threads would overwrite each other's data and crash. strtok_r() uses a explicit pointer parameter (save_ptr) passed by the caller, making it safe for multiple threads to use concurrently.


>A4: In Pintos, the kernel separates commands into a executable name and arguments.  In Unix-like systems, the shell does this separation.  Identify at least two advantages of the Unix approach.
Simpler Kernel: Doing text parsing in user space (the shell) keeps kernel code small, simple, and less vulnerable to crashes or security bugs.

More Features: The shell can easily support extra features like wildcards (*.c), variables, and pipes (|) before calling the kernel, making the system much more flexible.
